# Data Model: Database, Storage & Authentication Foundation

## Document

Represents metadata for one uploaded academic file.

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key, generated by database |
| `user_id` | UUID | Required, references Supabase Auth user identity |
| `filename` | Text | Required, non-empty original/display filename |
| `file_type` | Text | Required, one of PDF, DOCX, TXT, PPTX MIME/extension categories |
| `file_size` | Integer | Required, non-negative byte size; future upload flows must enforce the constitution size limit |
| `storage_path` | Text | Required for linking metadata to the stored object path |
| `created_at` | Timestamp with time zone | Defaults to current time |

Relationships:

- One Document has many Chunks.
- One Document maps to one raw Supabase Storage object path.
- Document rows are owned by `user_id`.

Validation:

- `filename` cannot be blank.
- `file_size` cannot be negative.
- `file_type` must represent an allowed academic file category.
- Normal client access must be restricted to the owning user.

## Chunk

Represents one extracted text segment linked to a Document.

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key, generated by database |
| `document_id` | UUID | Required, references `documents.id`, cascade deletes with the document |
| `text_content` | Text | Required, non-empty extracted text |
| `chunk_index` | Integer | Required, zero-based or one-based ordering selected by implementation and kept consistent |
| `created_at` | Timestamp with time zone | Defaults to current time |

Relationships:

- Many Chunks belong to one Document.
- Chunk ownership is derived through the parent Document.
- Later FAISS entries reference Chunk IDs for vector lookup and source reconstruction.

Validation:

- `text_content` cannot be blank.
- `chunk_index` cannot be negative.
- Client access must be restricted through the owning parent Document.

## Chat History Entry

Represents one question/answer interaction owned by a user.

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key, generated by database |
| `user_id` | UUID | Required for normal user entries; diagnostic backend rows may use a configured test user or service-role path |
| `question` | Text | Required, non-empty |
| `answer` | Text | Required, non-empty or explicit diagnostic response |
| `sources_cited` | JSONB | Required, defaults to an empty array |
| `created_at` | Timestamp with time zone | Defaults to current time |

Relationships:

- Chat History Entry belongs to one user.
- `sources_cited` can reference document/chunk identifiers and display citations in later chat flows.

Validation:

- `question` and `answer` cannot be blank.
- `sources_cited` must be JSON array-compatible data.
- Normal client access must be restricted to the owning user.

## Academic Document Storage Object

Represents a raw file stored in Supabase Storage bucket `academic-documents`.

| Field | Type | Rules |
|-------|------|-------|
| `bucket_id` | Text | Must be `academic-documents` |
| `name` | Text | Path should include user ownership boundary when uploads are implemented |
| `mime_type` | Text | Must match PDF, DOCX, TXT, or PPTX categories |
| `size` | Integer | Must satisfy upload size policy in future upload implementation |

Relationships:

- Storage object path is recorded by the Document metadata row.
- Storage policies should align object access with authenticated ownership.

Validation:

- Unsupported file categories must be rejected by upload policy or application boundary.
- Reads must be either authenticated ownership-aware or intentionally public for rendering.

## Connectivity Check Result

Represents diagnostic output from backend or frontend connectivity verification.

| Field | Type | Rules |
|-------|------|-------|
| `ok` | Boolean | Required |
| `status` | Text | Human-readable success or failure message |
| `source` | Text | `backend` or `frontend` |
| `record_id` | UUID/Text | Optional inserted/read diagnostic record identifier |
| `error` | Text | Optional sanitized error summary |

State transitions:

```text
not_configured -> configured -> write_attempted -> read_verified
                         \-> permission_aware_failure
                         \-> connection_failure
```

Validation:

- Failure responses must not expose secret values.
- Frontend connectivity must use only public `NEXT_PUBLIC_*` configuration.
- Backend connectivity may use backend-only Supabase configuration.
