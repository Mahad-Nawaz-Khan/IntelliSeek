# Data Model: Multi-Format Parsing Layer & Upload Pipeline

## Uploaded Academic File

Represents the browser-selected academic file before and during storage upload.

| Field | Type | Validation |
|-------|------|------------|
| `name` | string | Non-empty original filename |
| `size` | number | `0 < size <= 10_485_760` bytes |
| `extension` | string | One of `.pdf`, `.docx`, `.pptx`, `.txt` |
| `mime_type` | string | One of the allowed MIME types for PDF, DOCX, PPTX, TXT |
| `owner_user_id` | uuid/string | Required authenticated user identity |
| `storage_path` | string | Generated after upload; must include owner-aware path segment |

## Parse Request

Request sent from Next.js to FastAPI after a successful storage upload.

| Field | Type | Validation |
|-------|------|------------|
| `storage_path` | string | Required; must target `academic-documents` and match the requesting user scope |
| `filename` | string | Required; non-empty |
| `file_type` | string | Required; allowed extension or MIME category |
| `file_size` | number | Required; no larger than 10 MB |
| `user_id` | uuid/string | Required; must match the owner path and metadata record |

## Extracted Raw Text

In-memory result produced by the selected parser before Phase 4 chunking.

| Field | Type | Validation |
|-------|------|------------|
| `text` | string | Must be non-empty after trimming whitespace |
| `parser_type` | string | `pdf`, `docx`, `pptx`, or `txt` |
| `preview` | string | Optional response/debug preview limited to a safe short excerpt |

## Document Metadata Record

Persistent row inserted into the existing Supabase `documents` table only after parsing succeeds.

| Field | Type | Validation |
|-------|------|------------|
| `id` | uuid | Generated by PostgreSQL |
| `user_id` | uuid/string | Required owner identity |
| `filename` | string | Non-empty original filename |
| `file_type` | string | Allowed document type |
| `file_size` | number | No larger than 10 MB |
| `storage_path` | string | Non-empty unique storage object path |
| `created_at` | timestamp | Generated by PostgreSQL |

## Parsing Result

Service-facing and user-facing outcome after upload handoff.

| Field | Type | Validation |
|-------|------|------------|
| `ok` | boolean | `true` only when upload handoff, parsing, cleanup, and metadata insertion succeed |
| `status` | string | Human-readable accepted/parsing/success/failure state |
| `document_id` | uuid/null | Present only for successful metadata creation |
| `filename` | string | Mirrors parsed file on success or known failure |
| `text_preview` | string/null | Optional short preview only on successful parse |
| `error` | string/null | Sanitized failure reason on validation or parsing failure |

## State Transitions

```text
Selected -> Client Validated -> Uploaded -> Parse Requested -> Downloaded Temporarily -> Parsed -> Metadata Saved -> Ready
Selected -> Client Rejected
Uploaded -> Parse Failed -> Failed
Parse Requested -> Backend Rejected -> Failed
Downloaded Temporarily -> Cleanup Complete -> Failed or Ready
```

## Relationships

- One user owns many uploaded academic files.
- One successful parse creates exactly one `documents` row.
- One storage object path maps to one document metadata record for this phase.
- Extracted raw text is not durably stored as chunks until the next phase.
